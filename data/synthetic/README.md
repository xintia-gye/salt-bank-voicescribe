# Synthetic data

**Synthetic only — no real customers, audio, or PII.**

- `calls_metadata.jsonl` — one row per synthetic call (call_id, agent, language, duration, ground-truth category/sentiment).
- `transcripts/<call_id>.txt` — Romanian/English transcript text used as STT stand-in.
- `audio/` — optional TTS-rendered `.wav` (only if generated with `--audio`).

Generated by [`../generate_synthetic_calls.py`](../generate_synthetic_calls.py).
Regenerate: `python ../generate_synthetic_calls.py --n 40`

## Distributions (shaped, not uniform filler)

The generator samples from **explicit weighted distributions** (see
`CATEGORY_WEIGHTS`, `LANGUAGE_WEIGHTS`, `CATEGORY_DURATION` and the per-scenario
`SENTIMENTS` map in the script) so the dataset reflects a real Romanian retail-bank
support line, not a uniform mix:

- **Category** — lost/stolen cards dominate; app-technical is rarest:
  `card_lost ~32%`, `fraud_dispute / loan_inquiry / account_closure ~17-18%` each,
  `app_technical ~15%`.
- **Language** — Romanian bank, so calls skew RO with an English minority:
  `ro ~70%` / `en ~30%`.
- **Sentiment** — derived per scenario (people rarely call when all is well), giving
  a realistic skew toward `neutral`/`negative` over `positive`.
- **Duration** — varies by category (fraud & loan calls run longer than a quick card
  block or login fix), drawn from a per-category Gaussian clamped to 60-600s.

### Committed 40-call dataset

The committed `calls_metadata.jsonl` (n=40, seed=42) realizes this shape:

| dimension | distribution |
|---|---|
| category | card_lost 13, fraud_dispute 7, loan_inquiry 7, account_closure 7, app_technical 6 |
| language | ro 28, en 12 |
| sentiment | neutral 19, negative 14, positive 7 |

Running the script prints the realized distributions on every generation so the
shaping is verifiable, not assumed.
